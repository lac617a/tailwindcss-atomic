# Opciones

Pasa un segundo argumento a `withTailwindcssAtomic`, o el mismo objeto a los plugins de Vite / Webpack / Rollup / esbuild / Astro.

```ts
type Options = {
  /** Funciones cuyos argumentos de string se reescriben. */
  targetFunctions?: Set<string>;
  /** CSS de Tailwind ya compilado, para precargar el mapa (poco habitual). */
  tailwindCss?: string;
  /** Paquetes bajo node_modules cuyo JS sí se reescribe (design systems). */
  transpilePackages?: string[];
  /** CSS extra que no se atomiciza (además de node_modules). */
  ignoreCss?: Array<string | RegExp>;
  /** Clases con forma de utilidad que deben quedarse literales. */
  preserveClasses?: Array<string | RegExp>;
  /** Funciones cuyos strings se dejan intactos (por defecto `twIgnore`). */
  preserveFunctions?: Iterable<string>;
  /** Inventario JSON del mapa. `false` lo desactiva. */
  classMapFile?: string | boolean;
  /** Entradas CSS/SCSS extra para el warmup (monorepos: `scss/styles.scss`). */
  cssEntries?: string[];
  /**
   * Imprime un reporte antes/después al terminar el build.
   * `true` lo formatea; `"json"` emite una línea JSON.
   */
  report?: boolean | "json";
};
```

## Valores por defecto

- `targetFunctions`: `cn`, `clsx`, `classnames`, `cva`
- `preserveFunctions`: `twIgnore`
- `classMapFile`: `node_modules/.cache/tailwindcss-atomic/class-map.json`

```ts
withTailwindcssAtomic(nextConfig, {
  targetFunctions: new Set(["cn", "clsx", "tw"]),
});
```

## `report`

Muestra lo que cambió el compiler en este build: bytes de CSS (crudo y gzip), utilities únicas vs hashes atómicos compartidos, y el tamaño de los class strings (los nombres hasheados suelen ser un poco más largos).

```ts
withTailwindcssAtomic(nextConfig, {report: true});
```

O sin tocar la config:

```bash
TAILWINDCSS_ATOMIC_REPORT=1 pnpm build
TAILWINDCSS_ATOMIC_REPORT=json pnpm build
```

Los dev servers no imprimen para no ensuciar el HMR. En este repo, `pnpm report:apps` construye cada app de ejemplo con el reporte de texto.

## `transpilePackages`

Úsalo cuando los strings de clase viven en un paquete UI del workspace o en `node_modules`. Sin esto, Turbopack/Webpack pueden dejar `flex` en el JS publicado mientras el CSS de la app ya está hasheado.

## `cssEntries`

Fuerza el warmup de ficheros SCSS/CSS que no son la primera hoja que descubre Next. Típico en monorepos:

```ts
export default withTailwindcssAtomic(nextConfig, {
  cssEntries: ["scss/styles.scss"],
});
```

## `classMapFile`

Ruta personalizada, o `false` para no escribir el inventario.

```ts
tailwindcssAtomic({
  classMapFile: ".cache/atomic-class-map.json",
});
```

## `ignoreCss`

Salta la atomicización de CSS extra además de `node_modules` (hojas de terceros que importas al bundle).

## `preserveClasses`

Deja literales nombres que *parecen* utilidades Tailwind (`text-logo`, `flex-container`). Los strings coinciden exactos; las regex prueban el nombre sin escapar.

```ts
withTailwindcssAtomic(nextConfig, {
  preserveClasses: ["text-logo", /^flex-container$/],
});
```

<Callout>
  El mapa se escribe para que el rewrite de JS/HTML no dependa de que PostCSS haya corrido antes.
</Callout>
